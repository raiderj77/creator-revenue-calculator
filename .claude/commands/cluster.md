# Cluster Command

Map related creator questions and decisions without committing to a fixed topic-cluster buildout.

## Usage

`/cluster [topic or creator decision]`

## Rules

Read `docs/editorial-publishing.md` first. This command is read-only. It must not create pages, assign a publication cadence, or treat a cluster, pillar, or article count as a ranking requirement.

Do not invent authority scores, traffic forecasts, keyword difficulty, or success timelines. Do not copy competitor information architecture. Third-party keyword metrics must be labeled by source and capture date.

## Workflow

1. Start with verified Search Console queries/pages or a documented user/funnel problem.
2. Group queries by the creator decision they express, not merely by shared words.
3. Inventory maintained calculators, trackers, and approved published articles that already address each decision.
4. Identify overlap, cannibalization, retired-route conflicts, and opportunities to consolidate into an existing page.
5. Review live competitors only for intent and unmet needs; describe an original, source-supported contribution.
6. Map only contextual internal links that genuinely help the reader move between a decision, formula, tool, and next action.
7. Recommend as few pages as the evidence supports, including zero new pages.

## Output

Return an evidence table containing query group, creator job, current page/tool, GSC evidence, source needs, overlap risk, and recommended treatment: strengthen, consolidate, draft, defer, or reject. Mark facts, inferences, and unknowns separately. Do not draft or publish content.
